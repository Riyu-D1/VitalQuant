## Absolute-max vs power states (Table 3.10 p15–16)

Limits: VDD/VIO −0.3…4.2 V; VREGIN −0.3…5.8 V; D+/D− −0.3…VDD+0.3; all other pins: −0.3…5.8 V (VIO>3.3 V) or VIO+2.5 V (VIO≤3.3 V); IIO ±100 mA.

| State | Worst pin exposure | Result |
|-------|--------------------|--------|
| USB only (VBUS 5.25 max, no battery) | VREGIN 5.25≤5.8; VBUS sense 3.58≤VIO+2.5; UART pins driven by unpowered…n/a (ESP on) | OK |
| Battery only (VBUS=0, VDD_CP2102=0) | ESP32 UART idle-high 3.3 V into RXD via R72 10 k → ≤0.28 mA injection vs IIO ±100 mA; VBUS pin 0 | OK — bounded |
| Battery flat (VBAT<3.0) | same as battery-only | OK |
| Charging | VBUS present → powered; UART 3.3-V levels into VIO=3.3 V | OK |
| Skin-land fault | none — no patient-side pins | n/a |

## Sequencing
Bus-powered: VREGIN=VBUS only when USB attached; RSTb pulled to VDD_CP2102 via 1 kΩ, so device resets whenever rail collapses. No supply-ordering requirements in DS. The only powered/unpowered interface is UART via 10 k series — bounded as above.

## Passives
- C1 4.7 µF 0603 on VBUS: MLCC DC-bias derating at 5 V on 0603 ≈ −30..−50 % → effective ≥2.3 µF, acceptable for USB source cap (DS: 4.7 µF nominal).
- C9 4.7 µF 0402 on VDD_CP2102 @3.3 V: 0402 4.7 µF derates hard (≈−60 %) → ~1.9 µF effective; DS requires 4.7 µF nominal for the internal regulator — borderline but supplemented by C62 100 nF + system bulk; regulator stability verified in R5 bring-up.
- R63/R64 divider: 22.1k/47.5k, 5.25 V across 69.6 kΩ → 0.4 mW, fine.
- R62/R70-R73 0402: <1 mW.

## Findings
- None requiring hardware change. Bounded note: with battery-only power the ESP32 UART idles high into an unpowered CP2102N; injection ≈0.28 mA through R72/R73, far below the ±100 mA IIO rating and below typical latch-up concern; acceptable.
- D+/D− also connect (R102/R103 0 Ω) to ESP32-S3 native USB — both CP2102N and U1 share the connector pair; only one is intended active (firmware/strap), no contention issue since ESP USB is a device peripheral.
